# IDX Exchange — CRMLS MLS Analytics

Python data pipelines for analyzing California residential real estate transaction and listing data from the CRMLS (California Regional MLS). Built during an analytics internship at IDX Exchange.

---

## Project Overview

This project processes raw monthly MLS exports from CRMLS and transforms them into clean, analysis-ready datasets. It covers two parallel data streams:

- **Sold data** — closed residential transactions (January 2024 – April 2026)
- **Listing data** — active, pending, and historical residential listings (January 2024 – April 2026)

Each stream runs through a full 7-week pipeline: raw ingestion → EDA → mortgage rate enrichment → cleaning → feature engineering → outlier detection.

## Data Source

**CRMLS (California Regional MLS)** — the largest MLS in the United States, covering residential real estate transactions and active listings across California and parts of Nevada, Arizona, and Hawaii.

- **Sold files:** `CRMLSSold{YYYYMM}.csv` — one file per month, containing closed transactions
- **Listing files:** `CRMLSListing{YYYYMM}.csv` — one file per month, containing all listing records regardless of status (Active, Pending, Closed, Expired, etc.)

> **Important — Data Consistency Policy:** The February and March 2026 files (both Sold and Listing) are centralized datasets provided by the team. Do not replace these by re-running API pulls. All analysis should be based on the files currently in `data/` to ensure consistency across teams.

## Pipeline Overview

Both scripts (`sold_analysis.py` and `listed_analysis.py`) follow the same 7-stage structure. Run from the project root:

```bash
python scripts/sold_analysis.py
python scripts/listed_analysis.py
```

The scripts automatically detect any monthly CSV files in `data/` matching the `CRMLS*{YYYYMM}.csv` pattern. Adding new monthly files and re-running is all that is needed to update the analysis.

---

### Week 1 — Aggregation

Loads all monthly CSVs, concatenates them, and filters to `PropertyType == 'Residential'`.

**Validation printed:**
- Row count per individual file (append check)
- Total row count before and after concatenation
- `PropertyType` frequency table before filtering (shows full breakdown: Residential, ResidentialLease, Land, etc.)
- Row count before and after the Residential filter
- `PropertyType` frequency table after filtering (confirms only Residential remains)

**Output:** `sold_combined.csv` / `listed_combined.csv`

> **Listing-specific:** The listing CSVs have duplicate column headers from the API export (e.g., `PropertyType` appears twice). Pandas renames the second occurrence `PropertyType.1`. These `.1` duplicate columns are dropped immediately after loading.

---

### Weeks 2–3 — EDA (Exploratory Data Analysis)

Produces a full statistical profile of the dataset before any modifications.

- **Shape and dtypes** — confirms row/column counts and how pandas interpreted each column
- **Missing value analysis** — count and percentage of nulls per column, sorted worst-first; columns with >90% missing are flagged for removal in cleaning
- **Unique PropertyType values** — confirms filter worked correctly
- **Numeric distribution summary** — min, p25, median, mean, p75, p90, p99, max for: `ClosePrice`, `ListPrice`, `OriginalListPrice`, `LivingArea`, `LotSizeAcres`, `BedroomsTotal`, `BathroomsTotalInteger`, `DaysOnMarket`, `YearBuilt`

**Business questions answered:**
1. Residential vs. non-residential share of all records
2. Median and average close/list prices
3. Days on Market distribution (min, median, mean, p75, p90, p99, max)
4. % of homes sold above vs. at vs. below list price (sold) / price reduction rate (listed)
5. Date consistency issues — close date before listing date
6. Top 10 counties by median close/list price

**Reports saved:**
- `output/reports/sold_missing_value_report.csv`
- `output/reports/sold_numeric_distribution.csv`

---

### Weeks 2–3 — Mortgage Rate Enrichment

Fetches the **30-year fixed mortgage rate** (`MORTGAGE30US`) from the Federal Reserve's public FRED database, resamples from weekly to monthly averages, and merges onto each record by the month of its close/listing date.

- **Sold:** merged on `CloseDate` month
- **Listed:** merged on `ListingContractDate` month (the date the listing entered the market)

This allows downstream analysis of how rate changes correlate with sale prices and listing volumes over time.

**Output:** `sold_enriched.csv` / `listed_enriched.csv`

> If the FRED fetch fails (e.g., network timeout), the pipeline continues with `mortgage_rate_30yr` set to null. Re-running when connectivity is available will populate the rates.

---

### Weeks 4–5 — Data Cleaning

Produces a structurally valid, analysis-ready dataset.

**Steps:**
1. **Date conversion** — `CloseDate`, `PurchaseContractDate`, `ListingContractDate`, `ContractStatusChangeDate` converted from strings to datetime objects
2. **Column removal** — drops agent personal info (names, emails), AOR codes, school district fields, tax fields, system metadata, and any columns flagged as >90% missing in EDA
3. **Numeric type enforcement** — forces all numeric columns to float, converting any stray text values to NaN
4. **Invalid record removal** — removes rows where:
   - `ClosePrice` ≤ 0 or missing (sold) / `ListPrice` ≤ 0 or missing (listed)
   - `LivingArea` ≤ 0
   - `DaysOnMarket` < 0
   - `BedroomsTotal` or `BathroomsTotalInteger` < 0
5. **Date consistency flags** (added as columns, records not deleted):
   - `listing_after_close_flag` — listing date is after close date (impossible)
   - `purchase_after_close_flag` — contract date is after close date
   - `negative_timeline_flag` — either of the above
6. **Geographic quality flags** (added as columns):
   - `missing_coords_flag` — Latitude or Longitude is null
   - `zero_coords_flag` — coordinates are (0, 0), a common placeholder
   - `positive_longitude_flag` — Longitude is positive (California must be negative)
   - `out_of_state_flag` — coordinates fall outside California's bounding box (lat 32.5–42.1, lng -124.5 to -114.1)

**Output:** `sold_cleaned.csv` / `listed_cleaned.csv`

---

### Week 6 — Feature Engineering

Derives analytical columns from existing fields.

| Column | Formula | Purpose |
|---|---|---|
| `price_ratio` | ClosePrice / OriginalListPrice | Measures bidding competitiveness; >1 = sold over original ask |
| `price_per_sqft` | ClosePrice / LivingArea | Size-normalized price for cross-property comparison |
| `close_to_original_list_ratio` | Same as `price_ratio` | Explicitly named alias for reporting |
| `listing_to_contract_days` | PurchaseContractDate − ListingContractDate | Speed to contract; proxy for market demand |
| `contract_to_close_days` | CloseDate − PurchaseContractDate | Escrow length; proxy for transaction complexity |
| `close_year` / `close_month` / `close_yrmo` | From CloseDate | Enables time-series grouping and trend analysis |

> **Listed script difference:** `price_ratio` = ListPrice / OriginalListPrice (price reduction metric). Time columns are derived from `ListingContractDate` instead of `CloseDate`.

Also generates a **county-level segmented summary** (`output/reports/sold_county_summary.csv`) with median price, price/sqft, price ratio, DOM, and listing-to-contract days per county.

---

### Week 7 — Outlier Detection

Applies the **IQR (Interquartile Range) method** to flag statistical outliers without deleting any records.

**Method:**
- Q1 = 25th percentile, Q3 = 75th percentile, IQR = Q3 − Q1
- Lower fence = Q1 − 1.5 × IQR
- Upper fence = Q3 + 1.5 × IQR
- Values outside these bounds are flagged

**Fields:** `ClosePrice`, `LivingArea`, `DaysOnMarket` (sold) / `ListPrice`, `LivingArea`, `DaysOnMarket` (listed)

Flag columns (`ClosePrice_outlier_flag`, etc.) are added to the full dataset. Two output files are produced:

| File | Description |
|---|---|
| `sold_flagged.csv` | Full dataset with outlier flag columns — all rows preserved |
| `sold_final.csv` | Rows where no outlier flag is True — primary analytical dataset |

Before/after row counts and median comparisons are printed to confirm the outlier removal had the expected effect.
